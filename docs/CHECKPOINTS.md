## 1 执行与证据规则

按 CP01→CP11 严格顺序推进。当前 checkpoint 的范围必须实现完整，其新增测试与此前累计回归全部通过后，才能标记完成并进入下一个。可以在当前 checkpoint 内并行处理不冲突的代码/测试，但不能提前启动下个 checkpoint 的开发来掩盖当前失败。

状态只使用“未开始、进行中、失败待修复、已完成”。完成证据至少包含代码版本/提交标识、执行命令、环境、开始结束时间、测试总数/通过/失败/跳过、报告路径和缺陷处理记录。缺少 Docker、数据库、网络权限或工具时记未执行/失败待修复，不得将条件禁用、`skipTests`、`@Disabled` 或测试容器不可用时跳过作为绿灯。

每个门禁运行当前已冻结的测试清单；尚未进入开发范围的后续用例明确为未开始，不纳入当前通过率。最终必须覆盖全部 AT01–AT28 及详细用例文档的适用用例。修改预期结果须有需求/设计依据和评审记录，不能删除失败用例、降低断言、手工把任务改成功或用假的成功 Mock 代替待验证行为。

当前最终清单为 95 个用例及各自列明的参数变体，包含自动化、故障、安全、性能和人工审阅证据。CP11 必须做到 0 失败、0 阻塞、0 未执行、0 隐藏跳过；人工审阅由测试执行者记录审阅人和证据，不要求用户逐个 checkpoint 重新批准。需求或验收范围调整才另行提交评审。

供应商 Mock 是真实外部 HTTP 边界的可控替身；PG、事务、队列状态机和 Worker 必须使用实际实现。故障门禁必须保留任务表、attempt 历史、Mock 接收记录与业务副作用记录，不能只提供单张“tests passed”截图。

## 3 Checkpoint 明细

### CP01 版本、构建、数据库与测试基础

**范围：** 冻结 JDK/Boot/Maven/PG 与必要依赖版本；单 Maven 应用骨架；Wrapper；Flyway；JUnit 和真实 PG/HTTP Mock 测试入口；`APP_MODE` 基础；CI 门禁骨架。校验安全 DNS、自定义连接解析与强制总超时的客户端可实现性，不实现完整业务。具体安装/拉取按届时环境权限执行，本轮未执行。

**产物：** 构建文件/Wrapper、最小启动配置、迁移骨架和配置基础表、测试夹具与可重复命令、版本/依赖树记录、CI 配置、环境检查记录。所有依赖与镜像固定版本，记录镜像摘要，不使用 latest。

**依赖：** 用户评审确认；可用 JDK/容器或等价真实 PostgreSQL。当前仅确认本机 Java 17.0.20、Docker CLI 29.7.2，未发现全局 Maven；不把这些检查写成已完成 CP01。

**测试门禁：** 全新空库迁移成功、重复启动不重复迁移、schema 版本不匹配拒绝 ready；能够编译运行真实测试；Mock 接收到真实 HTTP；客户端禁跳转/自动重试、自定义 DNS、取消路径的最小可行验证；缺环境时测试必须报错而非跳过。版本维护/安全核验异常先修方案。

**完成证据：** [CP01 报告](reports/CP01/REPORT.md)，本地完整构建成功，28 次执行全部通过，失败/错误/跳过均为 0；CI 配置尚未在 GitHub 运行。状态：**已完成**。
